The [official docs](../../third_party/pump-public-docs) are pinned at commit `639b87fb45c3adeffa6f7c4a1bf0cb85e392bf22`. They publish client IDLs, not the deployed Rust instruction bodies. The payloads in `inputs/pump_fun/` retain allocated trailing zero padding. The [offline ELF inventory](elf-inventory.json) measures actual ELF extents of 1,934,800, 1,268,504, and 873,256 bytes, respectively. Each of the 125 published eight-byte instruction discriminators appears once as an `lddw` immediate in its corresponding pinned `.text` section. The [raw SBF dispatch map](dispatch-map.json) follows each adjacent/nearby signed branch and its direct call to **125 distinct wrapper entries** (56 Pump, 38 Pump AMM, 31 Pump Fees). This establishes selector and wrapper attribution, **not** local handler execution, full behavior, or exact source correspondence.

The docs' current frontier includes v3/v2 trading, multi-hop routes, synthetic migration, pump-coin quote chains, fee sweeps, and signed virtual quote reserves. [UPSTREAM_BRIEF.md](UPSTREAM_BRIEF.md) records the source and its limits. Optional Mayhem program accounts appear in Pump coin creation; that dependency is not yet a fourth core-program target in this lane.

The [exact-build checkpoint](../source_reconstruction/pump-fun-exact-build-feasibility.md)
pins ELF sections and ProgramData padding for all three programs. An initial
31-selector Pump Fees Rust/Anchor candidate builds deterministically but has
unsupported handler bodies and does not match the deployed ELF. This is the
start of a whole-program byte-comparison track, not recovered deployed source.

The [configuration snapshot](config-snapshot.json) pins one finalized canonical account per program. In a [signed, writable offline Surfpool sequence](admin-signed-surfpool.json), those copied accounts have their admin/authority fields replaced with a disposable local signer. Pump `set_max_curve_depth` changes 2→1, Pump AMM `disable` changes flags 0→8, and Pump Fees `set_claim_rate_limit` changes 0→600. An outsider-signed call for each instruction rejects with all three watched configuration accounts unchanged; each submitted local transaction charges its fee payer 5,000 lamports. The [independent receipt verifier](../../scripts/pump_fun_admin_surfpool_verify.py) checks six saved transaction signatures and exact post-state bytes. This establishes **one bounded writable current-ELF path per program** under synthetic authority, with no claim of live signer control or trading safety.

The [PumpSwap v2 fixture](amm-v2-trade-fixture.json) captures a finalized non-cashback WSOL pool, mints, reserves, fee config, and an authorized buyback recipient. In a [five-transaction signed offline Surfpool sequence](amm-buy-v2-signed-surfpool.json), a disposable trader buys 10,000,000,000 raw base units for 1,847,796 raw quote units, then sells 5,000,000,000 base for 901,089 quote. Missing trader signature and tighter buy/sell limits reject with watched state unchanged. User, pool, and buyback token amounts conserve per mint; accrued protocol plus creator fees equal the decrease in signed `virtual_quote_reserves` after each trade. The [independent verifier](../../scripts/pump_fun_amm_v2_surfpool_verify.py) checks five transaction signatures, source hashes, rollbacks, and accounting. Pool and fee accounts came from a **later captured state**; trader ATAs and WSOL funding are synthetic. This is a bounded current-ELF v2 path, not a live trade or full safety conclusion.

The [fresh Pump `create_v2` receipt](curve-create-v2-signed-surfpool.json) records a disposable mint, BondingCurve and Token-2022 vault made by the pinned current ELF, with 1 quadrillion raw-token mint supply and the Global-derived starting reserves. In the same offline ledger, [signed v3 trades](curve-fresh-trades-v3-signed-surfpool.json) create the user's ATA, buy 1 billion raw base for 28,310 lamports of trade input, then sell 500 million raw base for 13,804 lamports of trade output before the transaction fee. A one-lamport maximum buy and an excessive-minimum sell reject with protocol rollback. The [receipt verifier](../../scripts/pump_fun_curve_fresh_surfpool_verify.py) checks six signatures, token supply/reserve deltas, fee counters, buyback payment, rent and transaction-fee accounting. This is one fresh SOL-paired regular coin under disposable local keys; other quote modes and creator configurations remain open.

A subsequent [signed completion buy](curve-completion-signed-surfpool.json) takes the entire remaining 793,099,500,000,000 raw real-token reserve, sets `complete=1`, and leaves 206,900,000,000,000 raw base in the curve vault; a later signed sell rejects with rollback. The [offline `migrate_v2` sequence](curve-migrate-v2-signed-surfpool.json) first shows that the fixed 27 IDL accounts reject with 6027 and roll back. The [official client SDK's migration builder](sdk-migration-account-provenance.json) supplies a BoostVaultAuthority PDA and its wrapped-SOL ATA as two remaining accounts. With those accounts, the pinned Pump ELF creates a PumpSwap pool and moves the curve vault's remaining base into the pool. The 85,005,359,063-lamport real quote reserve is allocated as a 15,000,001-lamport migration fee, 67,405,853,773 raw wrapped-SOL units in the pool quote vault, and 17,584,505,289 in the BoostVault; the last amount equals the pool's signed virtual quote reserve. Curve reserves zero and pool token supply conserves. The [independent verifier](../../scripts/pump_fun_curve_migration_surfpool_verify.py) checks signatures, rollback, exact account derivations, and SOL/token accounting. This proves one current-binary, local regular-coin migration path; the SDK is client code, not the deployed Rust source.

On that exact newly migrated pool, a [five-transaction signed offline sequence](post-migration-amm-v2-signed-surfpool.json) creates and funds the user's wrapped-SOL ATA, buys 1,000,000,000 raw base for 415,919 raw quote, and sells 500,000,000 raw base for 202,821 raw quote. One-unit buy maximum and excessive sell minimum reject with rollback. The [post-migration verifier](../../scripts/pump_fun_post_migration_amm_surfpool_verify.py) ties the pool and user balances to the migration receipt, checks signatures and both mints' conservation, and reconciles protocol/creator fee counters to changes in signed virtual quote reserves. The AMM fee-config PDA differs from the curve fee-config PDA; using the curve config fails the AMM seed guard. This is a second bounded runtime context for AMM `buy_v2`/`sell_v2`, not two new instructions or a full pricing model. Other migration modes, pool variants and subsequent states remain open.

A separate [four-transaction Pump Fees withdrawal](fees-withdraw-signed-surfpool.json) uses the current pinned ELF with a **synthetic**, system-owned referral-vault PDA, 1,000,000 raw WSOL units in its ATA, and disposable user accounts. An unsigned user, wrong user PDA, and redirected recipient all reject with rollback; the valid user signature moves exactly 1,000,000 raw WSOL units and matching lamports from vault ATA to user ATA. The [offline verifier](../../scripts/pump_fun_fees_withdraw_surfpool_verify.py) checks four transaction signatures, token/lamport conservation, and unchanged outsider balance. No live accrued referral fees or entitlement has been established.

Next evidence: legitimate Fee accrual, additional quote mints and extensions, and more pool modes, then full pricing, authorization, migration, state and error models. No live transaction or wallet funds are used.
